# Что уходит в туннель

Три источника, от общего к частному. Все читаются при сборке конфига
(`vm/render-config.py`) и попадают в правила маршрутизации sing-box.

| Файл | Что это | Обновление |
|---|---|---|
| [`rulesets.list`](rulesets.list) | **Галочки**: готовые списки блокировок по сервисам | автоматически, раз в сутки |
| [`abroad-services.list`](abroad-services.list) | Ручной список доменов — то, чего нет в готовых наборах | вручную |
| [`abroad-networks.list`](abroad-networks.list) | Подсети для протоколов **без имени хоста** | вручную |

## Как это работает

Роутер ничего не решает: одно правило отправляет весь трафик из LAN
на шлюз. Решение принимает sing-box — снимает SNI каждого соединения
и сверяет со списками. Совпало — в туннель, не совпало — напрямую.

**Порядок сверки = приоритет** (D29): сначала свои подсети, потом свои
домены, и только потом готовые наборы. Если домен есть и там, и там,
исполняется то, что написано здесь, в ручных списках. До 2026-09-13 было
наоборот, и 36 записей `abroad-services.list` тихо не работали: галочка
`vernette:unavailable-in-russia fast` уводила `openai.com`, `claude.ai`
и ещё два десятка доменов с пометкой `own` на чужие серверы подписки.

**Куда применять.** Боевой шлюз — коробка Splitbox на `192.168.88.9`
(CT 125), а не CT 121 на `.6`. Файлы в этом каталоге — копия ноутбука;
у коробки свой `config.yaml`, который правит её панель.

## Галочки

`rulesets.list` — по строке на сервис. Раскомментировать = в туннель,
закомментировать = напрямую. Источник — [vernette/rulesets](https://github.com/vernette/rulesets),
списки собираются автоматически и содержат **и домены, и подсети**.

Доступны: `openai` `claude` `gemini` `grok` `copilot` `instagram` `x`
`linkedin` `whatsapp` `telegram` `discord-full` `discord-voice-chats`
`telegram-voice-chats` `tiktok` `youtube` `netflix` `spotify` `roblox`
`nintendo` `unavailable-in-russia` `rkn`.

Списки скачивает сам sing-box раз в сутки и кэширует на диск
(`/var/lib/sing-box/cache.db`), поэтому перезапуск не требует сети.
Никаких скриптов и планировщиков — это встроенная возможность.

## Когда нужен ручной список

`abroad-services.list` — для того, чего в готовых наборах нет:
аниме-сайты, облака IoT-устройств (Home Connect, UniFi), FaceTime,
Notion, Figma, Canva.

`abroad-networks.list` — для протоколов, которые **не передают имя хоста**,
и потому невидимы для правила по SNI. Сейчас там Telegram MTProto:
его приложения ходят на IP дата-центров напрямую.
Критерий попадания узкий: диапазон должен принадлежать одному сервису
целиком. Общие облачные диапазоны сюда класть нельзя — это правило
последняя инстанция, отсеивать попутчиков после него уже некому.

## Веб-интерфейс

Проще всего — **http://192.168.88.6:8088** (логин и пароль в `secrets/webui.env`).

Галочки по сервисам, поля для своих доменов и подсетей, статус туннеля
с точкой выхода. Кнопка «Применить» пересобирает конфиг, прогоняет
`sing-box check` и перезапускает службу. **Боевой конфиг заменяется только
после успешной проверки** — опечатка в списке не уронит интернет,
ошибка просто покажется на странице.

Файлы в этом каталоге и интерфейс — одно и то же: он их и читает, и пишет.

## Применить изменения из командной строки

```bash
./vm/render-config.py > /tmp/config.json && scp /tmp/config.json root@192.168.88.6:/etc/sing-box/config.json
```

```bash
ssh root@192.168.88.6 'sing-box check -c /etc/sing-box/config.json && systemctl restart sing-box'
```


## Резервные серверы

Подписка провайдера разбирается `vm/parse-subscription.py` в
`vm/sing-box/backup-outbounds.json`, оттуда попадает в группу автовыбора
`fast-out`. Обновление — systemd-таймером раз в сутки.

Что важно знать про эту конкретную подписку (Remnawave):

* **Нужен HWID.** Без заголовков привязки к устройству панель отдаёт
  заглушку «Напиши в поддержку» вместо серверов — в ответе это видно
  по `X-Hwid-Not-Supported: true`. Идентификатор постоянный,
  лежит в `secrets/hwid.env`, занимает один слот устройства.
* **Формат зависит от User-Agent.** Одному клиенту ссылки, другому
  sing-box JSON, третьему clash-YAML. Разборщик перебирает семь агентов
  и берёт ответ с наибольшим числом живых серверов.
* **Не все узлы годятся.** Профили «LTE обход» и «Россия → X» стоят
  на российских адресах: по задержке они выигрывают у зарубежных,
  и группа автовыбора предпочла бы именно их — трафик «за рубеж»
  остался бы в России. Отсеиваются по имени профиля и по голому IP.
