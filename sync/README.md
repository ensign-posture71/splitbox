# Список сервисов «за рубеж»

В Варианте B (D22) этот каталог содержит **только список** —
[`abroad-services.list`](abroad-services.list). Скриптов здесь больше нет.

## Как это работает

Роутер ничего не классифицирует: одно правило отправляет весь трафик
из LAN на контейнер. Решение принимает sing-box — он снимает SNI каждого
соединения и сверяет домен со списком. Совпало — в туннель, не совпало —
напрямую.

Список попадает в конфиг sing-box при сборке: `vm/render-config.py`
читает его и подставляет в правило маршрутизации.

## Добавить или убрать сервис

1. Правишь `abroad-services.list` — одна строка на домен, поддомены
   покрываются автоматически.
2. Пересобираешь и раскладываешь конфиг:

```bash
./vm/render-config.py > /tmp/config.json && scp /tmp/config.json root@192.168.88.6:/etc/sing-box/config.json
```

```bash
ssh root@192.168.88.6 'sing-box check -c /etc/sing-box/config.json && systemctl restart sing-box'
```

Всё. Никаких адресных списков, диапазонов, DNS-записей и прогрева —
это осталось в Варианте A и было удалено вместе с ним.

## Чего здесь больше нет и почему

`abroad-sync.py` синхронизировал список с роутером: сначала FQDN-записями
в address-list, потом DNS-статикой. Оба подхода упирались в то, что роутер
решает по адресу, а приложения живут доменами — см. O31 и D21 в журнале
решений. В Варианте B задача исчезла вместе с механизмом.
