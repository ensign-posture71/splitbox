# Splitbox

Умный VPN-шлюз в одной коробке: ваша VLESS-подписка + WireGuard для
устройств + блокировка рекламы + веб-панель, в которой всё настраивается
галочками.

Ставится одной командой на дешёвый VPS или домашний мини-ПК. Дальше —
вставить ссылку подписки и отсканировать QR телефоном. Больше ничего
знать не нужно.

## Чем отличается от «просто VPN»

Обычный VPN гонит в туннель **весь** трафик: банк ругается на иностранный
адрес, госуслуги не открываются, видео тормозит на лишнем крюке.

Splitbox решает **по каждому соединению отдельно** — по имени сайта:

| Политика | Куда идёт | Для чего |
|---|---|---|
| **мимо** | напрямую | российские сайты, банки, госуслуги |
| **свой** | ваш личный сервер | почта, нейросети, мессенджеры — то, что не хочется отдавать чужому серверу |
| **быстрый** | группа автовыбора из подписки | видео, музыка, игры — где важна скорость |

Политика ставится переключателем напротив каждого сервиса из готового
каталога (~65 штук: YouTube, Telegram, ChatGPT, Netflix, Steam…) или
для своего домена. Ничего не совпало — идёт напрямую.

## Установка

**На VPS** (вход для устройств через WireGuard):

```bash
curl -fsSL https://raw.githubusercontent.com/ensign-posture71/splitbox/main/install.sh | sudo sh
```

**Дома** (коробка обслуживает всю локальную сеть, устройствам ничего
ставить не надо):

```bash
curl -fsSL https://raw.githubusercontent.com/ensign-posture71/splitbox/main/install.sh | sudo sh -s -- --lan
```

Инсталлер поставит docker, скачает исходники в `/opt/splitbox`, соберёт
и запустит стек, а в конце напечатает ссылку на мастер настройки.
Повторный запуск обновляет установку, не трогая настройки.

Нужно: Debian/Ubuntu (или другой дистрибутив с docker), 1 ГБ памяти,
amd64 или arm64. Для домашнего режима — ещё и **rootful docker**
(в rootless-режиме контейнер не может управлять маршрутизацией).

## Первый запуск

Панель работает по HTTPS с самоподписанным сертификатом: браузер один раз
предупредит — это нормально, коробка выпускает его сама, настоящий взять
неоткуда. Мастер проведёт за семь шагов:

1. придумать пароль к панели;
2. выбрать **режим работы** — «домашний шлюз» (только локальная сеть) или
   «полноценный» (плюс устройства извне через WireGuard);
3. указать **внешний адрес** — только для полноценного режима, и его можно
   пропустить, заполнив позже;
4. вставить ссылку подписки (`https://…`) или своего сервера (`vless://…`);
5. назвать первое устройство;
6. отсканировать QR приложением **WireGuard** (App Store / Google Play);
7. увидеть «всё работает» и адрес, с которого вы теперь выходите.

Разумный набор сервисов включается сам — коробка полезна сразу, без
единой настройки. Режим работы потом меняется в настройках.

## Блокировка рекламы

AdGuard Home идёт в комплекте и работает сразу. Его собственный интерфейс —
списки, журнал запросов, статистика по клиентам — живёт на **порту 3000**,
ссылка и пароль показаны в настройках панели. Учётка создаётся при первом
запуске: интерфейс управляет DNS всей сети, и без пароля его оставлять
нельзя. В домашнем режиме он доступен на адресе коробки, в режиме VPS
порт наружу не публикуется — туда попадают только через WireGuard.

## Что в составе

Три контейнера в одном сетевом пространстве плюс разовый init:

| Компонент | Роль |
|---|---|
| **gateway** | [sing-box](https://sing-box.sagernet.org/): WireGuard-сервер для устройств, маршрутизация по имени сайта, перехват трафика локальной сети. Плюс супервизор: держит сетевую обвязку, следит за туннелем, перезапускает при сбоях |
| **adguard** | [AdGuard Home](https://adguard.com/adguard-home/overview.html): DNS для всех клиентов и блокировка рекламы |
| **app** | веб-панель (FastAPI): мастер настройки, каталог сервисов, устройства с QR-кодами, подписки, свои списки |
| **init** | разовая инициализация тома при старте |

Наружу торчат ровно два порта: WireGuard (UDP 51820) и веб-панель.
Всё остальное — DNS, API управления, метрики — доступно только внутри
стека.

### Структура репозитория

```
compose.yaml         базовый стек (режим VPS)
compose.lan.yaml     оверлей режима домашнего шлюза
compose.dev.yaml     оверлей разработки (код без пересборки образа)
install.sh           установка одной командой
pack.sh              сборка архива для раздачи без GitHub
catalogs/            каталог сервисов и источники списков блокировок
docker/gateway/      образ и супервизор сетевого контейнера
docker/app/          образ веб-панели
core/                пакет splitbox: вся логика (см. ниже)
docs/ARCHITECTURE.md подробно о внутреннем устройстве
```

Внутри `core/splitbox/`:

| Модуль | За что отвечает |
|---|---|
| `model.py` | схема `config.yaml` — единственный источник истины |
| `store.py` | атомарное чтение и запись настроек |
| `render.py` | сборка конфига sing-box из настроек |
| `subs.py` | разбор VLESS-подписок (4 формата панелей) |
| `wg.py` | ключи WireGuard и конфиги устройств |
| `apply.py` | применение: собрать → проверить → заменить → перезапустить |
| `health.py` | проверка туннеля настоящим запросом наружу |
| `adguard.py` | стартовый конфиг и управление блокировкой |
| `api/` | веб-панель: маршруты, шаблоны, авторизация |

## Сколько угодно источников

Подписок и личных серверов может быть любое количество. На вкладке
**Серверы** у каждого источника отмечается, в какие группы он входит:

* **в «свой»** — доверенный выход для личного (почта, нейросети, банки);
* **в «быстрый»** — участие в гонке за скорость (видео, музыка, игры).

Подписки по умолчанию попадают только в «быстрый»: чужой сервер видит
весь проходящий через него трафик, и пускать туда личное — осознанное
решение, а не умолчание.

Для каждой группы отдельно настраивается, **как выбирается сервер**:

| Стратегия | Что делает |
|---|---|
| **быстрейший** | замеряет задержку и берёт лучший; настраиваются период проверки и допуск в миллисекундах |
| **закреплённый** | всегда один и тот же сервер, пока он жив — когда важна предсказуемость выхода |

Допуск — насколько новый сервер должен выигрывать, чтобы туннель на него
переключился: маленький допуск даёт частые перескоки.

## Статистика

Вкладка **Статистика** показывает за час, сутки, неделю или месяц:

* состояние машины — процессор, память, подкачка, диск: текущее значение,
  среднее и пик, у каждого свой мини-график;
* скорость сети по интерфейсам и число открытых сокетов (TCP и UDP);
* время работы, расход самой панели, адреса коробки;
* сколько запросов обработал AdGuard и сколько из них заблокировал;
* график трафика туннеля — принято и отдано во времени;
* куда уходит трафик — доли «свой сервер», «группа скорости», «напрямую»;
* сколько трафика у каждого устройства;
* через какие конкретно серверы он шёл;
* кто на какие сайты ходил (отключается в настройках).

Данные собираются из внутреннего API sing-box каждые две секунды и лежат
в SQLite внутри коробки: поминутно двое суток, по часам — весь срок
хранения. Наружу не уходят никуда, Prometheus и Grafana не нужны.

Ограничение честное: видны только живые соединения, поэтому соединение,
успевшее открыться и закрыться между двумя опросами, в разбивку не
попадёт. Заметный трафик — видео, загрузки, мессенджеры — живёт дольше
и учитывается полностью.

## Как это работает

```
устройство (WireGuard)  ┐
                        ├──►  sing-box  ──► решение по имени сайта ──┬──► ваш сервер
локальная сеть (шлюз)   ┘         │                                  ├──► группа автовыбора
                                  ▼                                  └──► напрямую
                            AdGuard (DNS + реклама)
```

1. Трафик попадает в коробку двумя путями: от устройства с WireGuard либо
   от любого устройства сети, если коробка назначена шлюзом.
2. DNS-запросы перехватываются и уходят в AdGuard — реклама отсекается
   на этом шаге, наружу запросы не утекают.
3. sing-box подсматривает имя сайта в начале соединения и сверяет со
   списками: готовые наборы, ваши домены, ваши подсети.
4. Совпало — соединение уходит по назначенной политике. Не совпало —
   напрямую.

Когда вы что-то меняете в панели, конфиг **сначала собирается во
временный файл и проверяется** штатной проверкой sing-box, и только
после успеха заменяет боевой. Опечатка в списке не может уронить
интернет.

Раз в сутки коробка сама обновляет список серверов из подписки и списки
блокировок. Пустой ответ подписки не затирает рабочий резерв.

Подробности, схемы отказоустойчивости и объяснение принятых решений —
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Если что-то сломается

Главный принцип: **сломанный туннель не оставляет людей без интернета.**

- В режиме шлюза коробка сама замечает, что туннель мёртв (проверяет
  настоящим запросом наружу, а не «жив ли процесс»), и снимает перехват —
  сеть продолжает работать напрямую. Починился — перехват возвращается сам.
- В режиме VPS выключите тумблер в приложении WireGuard, и всё вернётся.
- Kill-switch отсутствует намеренно: он противоречит этому принципу.

## Честные ограничения

- **В режиме VPS «российские сайты как из дома» не работают** — весь
  прочий трафик выходит с адреса вашего VPS. Умное разделение с
  сохранением местного адреса даёт только домашний режим.
- Домашний режим требует ядра Linux с nftables и tproxy: обычные
  Debian/Ubuntu/Raspberry Pi OS подходят, Synology и Docker Desktop —
  нет (там доступен только режим WireGuard).
- WireGuard работает в пространстве пользователя: это медленнее ядерного,
  но достаточно для домашних задач и не требует особых прав.
- Провайдер может резать UDP — тогда WireGuard не установит соединение.
  Обхода этого пока нет.

## Раздать без GitHub

Если у друга нет доступа в GitHub, соберите архив:

```bash
sh pack.sh          # получится splitbox-<дата>.tar.gz
```

Другу: `tar xzf splitbox-*.tar.gz && sudo sh splitbox/install.sh`

## Разработка

```bash
cd core
python3 -m venv .venv && .venv/bin/pip install -e ".[api,dev]"
.venv/bin/python -m pytest                    # 91 тест
SPLITBOX_STATE=/tmp/sb .venv/bin/uvicorn splitbox.api.app:app --reload
```

Эталонные конфиги (`core/tests/golden/`) проверяются настоящим
`sing-box check` — любое изменение сборки конфига видно в диффе.

Локальный стенд: `docker compose up -d --build`, панель на
http://localhost:8443. Правки кода без пересборки образа — оверлей
`compose.dev.yaml`. Проверить режим шлюза на macOS нельзя: нужно
настоящее ядро Linux, см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Происхождение

Splitbox вырос из домашней связки MikroTik + sing-box, которая три
месяца работала на одну квартиру. Продукт унаследовал от неё все
шишки: почему проверять надо результат, а не процесс; почему конфиг
меняется атомарно; почему узлы подписки внутри России нельзя пускать
в группу автовыбора. Каждая такая деталь помечена в коде комментарием
с объяснением — они не украшение, а память об отладке.
