Документ для входа в проект «с нуля» — например в новой сессии без контекста.

## 1. Что построено

Все устройства дома получают три пути трафика **без настройки на самих
устройствах**:

| Путь | Куда | Кто решает |

| «за рубеж», быстрый | группа из своего VPS + 17 серверов подписки | sing-box, выбор по задержке |
| напрямую | обычный WAN | всё, что не совпало со списками |
| «на работу» | wg-work → сеть работодателя | роутер, маршруты `10/8` и `172.16/12` в main |

Путь «на работу» включён 2026-08-18 (D23): туннель wg-work на роутере,
конфиг от админов — `secrets/staff_lyurov2.conf`. Классификатор для него
не используется — рабочие подсети лежат в `policy-exempt`, поэтому трафик
идёт по обычным маршрутам таблицы `main`. Рабочие домены `mosgortrans.*`
резолвятся через DNS работы (условные апстримы в AdGuard) — split-horizon
сам возвращает внутренние адреса, которые уходят в туннель.

## 3. Как это работает

**Роутер ничего не классифицирует.** Одно правило mangle отправляет весь
трафик из LAN в таблицу `table_vps`. Исключения — только локальные адреса
и трафик самих шлюзов.

**Куда ведёт `table_vps` (важно, O41).** С 2026-08-30 активен маршрут на
**коробку Splitbox, CT 125 `192.168.88.9`** (`distance=1`) — весь домашний
трафик обслуживает она, код в [`product/`](../product/). Ниже неё сразу
fail-open прямо в WAN (`distance=10`): при падении коробки дом остаётся
с интернетом, но без туннелей. Промежуточный резерв CT 121 `.6` убран
2026-09-21 (D31). **Правки списков, которые должны подействовать сегодня,
применяются на коробке**, а не только в `vm/`.

**Решение принимает sing-box** на шлюзе: снимает SNI каждого соединения
и сверяет с тремя источниками (порядок правил = приоритет, D29):

1. свои подсети → по политике строки;
2. свои домены → по политике строки;
3. готовые наборы блокировок с политикой `fast` → группа автовыбора;
4. готовые наборы с политикой `own` → свой VPS;
5. **всё остальное → напрямую**.

Свой список выше наборов намеренно: ручная запись точечная, набор — оптовый.
До 2026-09-13 было наоборот, и 36 записей своего списка не исполнялись (O38).

Перехват транзитного трафика — TPROXY + nftables + `ip rule`,
служба `singbox-tproxy`.

## 5. Как менять

**Обычный путь — веб-интерфейс** `http://192.168.88.6:8088`:
галочки по 65 сервисам, таблицы своих доменов и подсетей, у каждой записи
переключатель `мимо / свой / быстрый`. Кнопка «Применить» пересобирает
конфиг, прогоняет `sing-box check` и перезапускает службу.
**Боевой конфиг заменяется только после успешной проверки.**

**Из командной строки** (после правки файлов в `sync/`):

```bash
./vm/render-config.py > /tmp/c.json && scp /tmp/c.json root@192.168.88.6:/etc/sing-box/config.json
```

```bash
ssh root@192.168.88.6 'sing-box check -c /etc/sing-box/config.json && systemctl restart sing-box'
```

Файлы в `sync/` на ноутбуке и в `/opt/vpn-config/sync/` на контейнере —
**две отдельные копии**. Веб-интерфейс правит вторую; после правки через
него стоит забрать файлы обратно в репозиторий.

## 7. Грабли, на которые уже наступили

Каждая стоила времени — не наступайте повторно.

**Fasttrack ломает policy routing** (O6). Помеченный трафик обязан быть
исключён из fasttrack, иначе метится только первый пакет соединения.

**Контейнер отвечает клиенту мимо роутера** (O30). Они в одной подсети,
поэтому ответ идёт по L2 напрямую. Роутер видит половину диалога,
conntrack застревает, пакеты становятся `invalid`. Отсюда stateless-разметка
и отдельное правило `accept` для `invalid` в сторону контейнера.
**Notrack здесь использовать нельзя** — untracked-пакеты не проходят
masquerade, и при fail-open интернет ляжет у всех.

**«Спросил другой резолвер» — иллюзия** (O43). Правило `hijack-dns` стоит
первым, поэтому любой DNS-запрос из сети отвечает AdGuard коробки, кем бы
ни был адресован. Проверяется за секунду: `dig @192.0.2.1 example.com`
— адрес из TEST-NET-1 не ведёт никуда, и если ответ пришёл, спрашивали
не того. Сравнивать резолверы можно только DoH/DoT-запросами напрямую.

**Апстрим DNS может врать про регион** (O43, D30). `api.themoviedb.org`
отдавал `127.0.0.1` — не из-за блокировки, а потому что TMDB блокирует
российские подсети, а резолвер сообщал ему регион через EDNS Client Subnet.
Апстримы обязаны быть нефильтрующими **и** не передающими ECS: сейчас это
Cloudflare и Quad9, каждый в DoH и DoT. Google Public DNS не годится —
передаёт ECS; AdGuard DNS, OpenDNS, bebasid не годятся — фильтруют.
AdGuard балансирует между апстримами, поэтому один негодный в списке даёт
не поломку, а **орлянку** — худший вид поломки.

**Перехват tproxy ловит и собственные docker-сети** (O42). Цепочка
`splitbox-tproxy` фильтровала только по адресу назначения, поэтому трафик
контейнеров коробки уезжал в туннель и не возвращался — сборка образов
не могла достучаться до PyPI. Отсюда дедлок обновления: `install.sh` делает
`up -d --build`, сборке нужна сеть, а чинит её ровно тот образ, который
эта сборка и собирает. Выход — собрать мимо бриджа:
`docker build --network=host …`. Исправлено строками `iifname "docker*"
return` / `iifname "br-*" return`, но проверять стоит и то, **не старше ли
образ исходников**: коробка так прожила 13 дней.

**Порядок правил — это приоритет, и он невидим** (O38, D29). Пока rule-set
стоял выше своего списка, галочка напротив сервиса молча затирала
переключатель напротив домена: `openai.com own` лежал в файле, светился
в интерфейсе — и уходил через чужие серверы подписки. Конфиг при этом
валиден, `sing-box check` молчит, сайты открываются. Порядок закреплён
тестом `test_own_lists_outrank_rulesets`; комментария недостаточно.

**`sing-box check` не ловит устаревшее** (O40). `download_detour` объявлен
устаревшим в 1.14.0, но предупреждение выводится только в рантайме,
в журнале службы. После каждого обновления sing-box — смотреть
`journalctl -u sing-box` с момента старта, а не полагаться на check.

**Сначала проверить, что цель существует** (O39). Три из четырёх «сломанных»
доменов в ТЗ на ремонт оказались NXDOMAIN. Шаг «резолвится ли имя вообще»
стоит секунду и закрывает вопрос до всякой теории про маршруты.

**Стеринг по IP не работает для CDN** (O26, O31). Instagram и YouTube
отдают разным клиентам разные адреса. Именно поэтому схема ушла
от списков адресов к решению по домену.

**Проверка должна идти боевым путём** (O21, O32). Дважды health-check был
зелёным при сломанной системе: сначала потому что проверял туннель мимо
tproxy, потом потому что проба уходила в `direct`.

**`PartOf=` в systemd пробрасывает остановку, но не запуск** — снятая
обвязка tproxy не возвращалась, и возникала петля маршрутизации.

**`parse_qs` выбрасывает пустые значения** — параллельные списки формы
разъезжались, и записи получали чужую политику. Нужен `keep_blank_values=True`.

**Подписка отдаёт разное разным клиентам** и требует HWID. Без заголовков
привязки к устройству панель Remnawave возвращает заглушку
«Напиши в поддержку» вместо серверов.

**Узлы подписки внутри РФ отсеиваются намеренно** — по задержке они
выигрывают у зарубежных, и группа автовыбора предпочла бы их,
оставив трафик «за рубеж» в России.

## 8. Диагностика

```bash
ssh root@192.168.88.6 'journalctl -u sing-box -f'
```

```bash
ssh root@192.168.88.6 'systemctl status sing-box singbox-tproxy vpn-ui'
```

Проверить, куда ушло соединение — по логу sing-box: `outbound/vless[reality-out]`
это свой VPS, `outbound/vless[bk-*]` резерв, `outbound/direct[direct]` мимо туннеля.

Отличить «сломался транспорт» от «сломался конфиг» (O21):

```bash
dig @192.168.88.1 router.lan
```

Имя знает только роутер: ответ есть — значит он жив и отвечает,
проблема в чём-то другом.

## 9. Проверенные показатели

Замеры с LAN-клиента, актуальны на момент передачи:

| | |
|---|---|
| через свой VPS | Instagram 0.76 с, Telegram 0.22 с, Bosch 0.37 с |
| через быструю группу | YouTube 0.33 с, Spotify 0.39 с, Twitch 0.22 с |
| напрямую | `ya.ru` 0.04 с, госуслуги 0.04 с |
| пропускная способность | 239 Мбит/с через контейнер против 273 без него |
| CPU роутера | 1–5% в покое, 18–31% под нагрузкой |

Fail-back проверен учениями: остановка sing-box переводит маршрут в
`inactive`, трафик уходит напрямую, интернет у дома продолжает работать.

**Уровень логов sing-box — не косметика** (O45). `"level": "info"` на шлюзе,
через который идёт весь дом, даёт по три строки на соединение: 13 ГБ
json-лога докера за десять часов и гипервизор, треть времени стоящий
в ожидании диска. Держать `warn` и предел `max-size` в compose.

**AdGuard сам ставит себе `ratelimit: 20`** (O46), и считает он не на
клиента, а на подсеть `/24`. С перехватом DNS это один лимит на весь дом.
Лишнее отбрасывается молча. Для домашнего резолвера нужен `ratelimit: 0`.

**Кириллица в командах RouterOS через SSH калечит правило** (D31). Комментарий
по-русски съел `dst-address` и `dst-port` у dstnat-правила — оно завернуло
весь UDP. Комментарии в командах только латиницей, и каждое созданное правило
печатать обратно и читать глазами.

**Мёртвый пир WG с `persistent-keepalive` вытесняет журнал роутера** (O47).
Роутер бесконечно долбится в несуществующий эндпоинт и пишет об этом каждые
две минуты. Журнал кольцевой — полезное в нём не доживает.

**Туннель на работу молчит — меняй исходящий порт** (O48). Если `wg-work`
не получает ответов, а передача идёт, дело почти наверняка в застрявшем
отображении NAT на пути. Смена `listen-port` (переменная `wgListenPort`
в `router/15-wg-work.rsc`) поднимает туннель за секунды. Проверять надо
сниффером — `/tool sniffer quick ip-address=<эндпоинт>` снимает пакеты
до файрвола и сразу показывает, уходят ли наши и возвращаются ли чужие.

**Один конфиг WireGuard на два устройства не работает** (O48). Сервер шлёт
трафик пира туда, откуда пришло последнее валидное рукопожатие. Пока
рабочий конфиг поднят на телефоне, роутер остаётся без туннеля. Нужен
отдельный конфиг со своим ключом.
