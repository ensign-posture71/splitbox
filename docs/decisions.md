# Журнал решений

Дополняет `architecture.md` (F1–F8 там). Здесь — только то, что решено/обнаружено
в ходе исполнения. Каждая запись: решение, дата, обоснование.

## D1 — §5: Вариант A (2026-08-17)
Роутер стерит по IP-address-list `abroad`, мозг (домены, geosite, автообновление) — на VM.
VM пушит IP-список на роутер.
**Почему:** fail-open важнее доменной точности для домохозяйства (см. §5 architecture.md).
**Следствие:** нужен sync-скрипт `sync/`; отказ VM = abroad не работает, остальное живёт.

## D2 — Линк роутер↔VM: общий LAN-сегмент (2026-08-17)
VM в `192.168.88.0/24` со статическим IP. Отдельный VLAN и WG p2p отклонены.
**Почему:** максимальная простота и диагностируемость; WG p2p — лишний CPU на слабом hAP ac² (F1).
**Открыто:** конкретный IP для VM — вне DHCP-пула роутера (уточнить после baseline).

## D3 — VPS: реюз существующего VLESS+Reality (2026-08-17)
Шаг 2 сводится к сбору клиентских параметров и проверке, а не к развороту.
**Нужны от владельца:** адрес, порт, UUID, public key, shortId, SNI/dest, flow.
**Хранение:** `secrets/`, вне Git.

## D4 — Доступ: SSH с рабочего Mac (2026-08-17)
Чтение (export, диагностика) и применение — по SSH. Пароли не передаются, авторизация по ключу.
