# Плоскость 2 — «мозг обхода» (шаг 3)

Среда: **непривилегированный LXC** на Proxmox, `192.168.88.6` (D9, D13).
Не VM, как предполагал §4.2 архитектуры — отсюда требования к TUN и NET_ADMIN.

## 3.1 Контейнер

| Параметр | Значение | Обоснование |
|---|---|---|
| Тип | LXC, непривилегированный | D13 |
| Ресурсы | 4 vCPU / 8 ГБ / диск 8–10 ГБ | выделено владельцем; sing-box съест доли этого |
| Шаблон | Debian 13 minimal | предсказуемый systemd, свежий nftables |
| Сеть | bridge в LAN, **статический** `192.168.88.6/24`, gw `192.168.88.1` | вне DHCP-пула `.10-.254` (O7) |
| DNS контейнера | `192.168.88.45` (AdGuard) | D6 — цепочка резолвинга сети не меняется |

Дополнения в `/etc/pve/lxc/<CTID>.conf` — проброс TUN:

```
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net dev/net none bind,create=dir
```

`CAP_NET_ADMIN` внутри сетевого namespace непривилегированного контейнера доступен
штатно, поэтому nftables и TPROXY должны работать без перевода в привилегированный
режим. **Проверить фактически** на хосте перед тем, как строить дальше: если TPROXY
не поднимется — переключаемся на привилегированный (D13 допускает).

## 3.2 sing-box

Роль по §4.2: принять abroad-трафик от роутера, отдать его в VLESS+Reality на VPS,
вернуть в direct то, что случайно попало в поток (RU-домены).

**Приём трафика.** Роутер маршрутизирует помеченные пакеты на `.6`, где dst — чужой
публичный IP. Значит контейнеру нужно:
- `net.ipv4.ip_forward=1`;
- `ip rule` + `ip route local` для TPROXY-таблицы;
- nftables-правило `tproxy` на транзитный трафик;
- inbound sing-box типа `tproxy`.

**Отдача.** Outbound VLESS+Reality, параметры в `secrets/reality-vps.env` (D10):
сервер `fear.freemyip.com:443`, `flow=xtls-rprx-vision`, uTLS `chrome`.
Помни O15 — эндпоинт на бесплатном DDNS, адрес может смениться.

**Конфиг** — `sing-box/config.template.json`. Плейсхолдеры `${...}` подставляются
из `secrets/reality-vps.env` при развёртывании.

> Схема конфига sing-box заметно менялась между 1.9 / 1.11 / 1.12 (`sniff` уехал
> в route-actions, outbound `block` объявлен устаревшим). Шаблон написан под
> текущую стабильную ветку и **обязан пройти `sing-box check -c config.json`
> перед первым запуском** — не принимать на веру, проверять на той версии,
> которая реально встанет в контейнер.

## 3.3 Наполнение списков

Два независимых потока в address-list `abroad` на роутере (оба — через `sync/`):

1. **IP-база**, разово + периодически: `ips_refilter` (28 855) + `ips_antifilter` (896).
   Ложится целиком, замеры O18 подтверждают: ~13.7 МБ RAM, ~110 с на полный проход.
2. **Доменный поток** (D11): query-лог AdGuard → домены из abroad-набора →
   их резолвленные IP → address-list. Оседает только реально используемое.

Плюс третий, не требующий `sync/` вовсе: **curated-домены прямо в address-list
FQDN-записями** — роутер резолвит их сам (O19). Годится для AI-сервисов
(OpenAI/Claude/Gemini/Copilot) и `domains_community` (124 записи).

## Порядок работ

1. Контейнер, сеть, статика, TUN — проверить, что TPROXY поднимается.
2. sing-box: установка, конфиг, `sing-box check`, запуск, проверка handshake с VPS.
3. Транзит: nftables + ip rule, проверить, что трафик от роутера доходит и уходит в Reality.
4. Переключить `table_vps` на `.6` (`router/10-routing-tables.rsc`, ФАЗА 2),
   прежний маршрут опустить до `distance=10` — это и есть fail-open из D1.
5. `sync/` — наполнение списков.

Шаги 1–3 не трогают домашний трафик вообще: роутер продолжает слать abroad мимо
контейнера, пока не выполнен шаг 4.
